    14. Apêndices

    14.1. Instalação do Flutter

    O SDK do [Flutter] pode ser baixado em docs.flutter.dev (selecione [Windows] e depois [Android]). É uma simples pasta compactada, que você extrai em uma pasta SEM espaços nem caracteres acentuados (por exemplo, [C:\dev\flutter]), e depois adiciona a subpasta [bin] à variável de ambiente [Path] do usuário. O SDK do [Dart] está incluído. Verifique a instalação em um novo console:

    1
2
    flutter --version
flutter doctor

    [flutter doctor] verifica tudo o que o [Flutter] exige: SDK, [Android] e suas licenças, [Chrome], [Visual Studio] (para aplicações [Windows]), dispositivos conectados e acesso à rede. Cada linha é precedida por uma marca de verificação [√] se estiver tudo certo, por um X [X] ou por um ponto de exclamação [!] caso contrário, com instruções sobre o que fazer listadas abaixo. [flutter doctor -v] fornece detalhes (versões, caminhos).

    A linha “Visual Studio” só se aplica a aplicações [Windows] (a pasta de exemplos [windows/] ): ela pode continuar com erro se você mira apenas dispositivos móveis e a web.

    No [Windows], projetos que usam pacotes com código nativo ([shared_preferences]...) exigem o “modo de desenvolvedor” do sistema: [flutter pub get] avisa isso (“Building with plugins requires symlink support”). Você pode habilitá-lo em Configurações / Sistema / Para desenvolvedores (comando [start ms-settings:developers]).

    14.2. Instalação do Android Studio e de um emulador

    O [Android Studio] pode ser baixado em developer.android.com/studio. Ele não serve para escrever código, mas para instalar o SDK do [Android] e criar um emulador:

    • Na primeira execução, o assistente instala o SDK do [Android];
    • menu More Actions / SDK Manager, aba SDK Tools: marque “Android SDK Command-line Tools”, de que o [Flutter] precisa;
    • em um console: [flutter doctor --android-licenses], e aceite as licenças;
    • menu More Actions / Virtual Device Manager: crie um celular virtual (por exemplo, um “Pixel”) com uma imagem de sistema recente. Clique no botão ▶ para iniciá-lo; [flutter devices] o detectará então com o nome [emulator-5554]. Você também pode iniciá-lo sem abrir o [Android Studio]: [flutter emulators] lista os emuladores, e [flutter emulators --launch <name>] inicia um deles.

    Para um celular real: em Configurações / Sobre o telefone, tocar sete vezes em “Número da versão” exibe as “Opções do desenvolvedor”, onde você pode habilitar a “Depuração USB”. Quando conectado ao computador, o celular pedirá que você autorize o computador; [flutter devices] o detectará então.

    14.3. Instalação do Visual Studio Code

    O [Visual Studio Code] é baixado em code.visualstudio.com. No painel Extensions (Ctrl-Shift-X), instale a extensão [Flutter] (do [Dart Code]), que também instala a extensão [Dart]. Elas oferecem:

    • autocompletar código, validação do código durante a digitação (com as regras do [analysis_options.yaml]), navegação até a definição de um widget ou de uma classe e renomeação em todo o projeto;
    • formatação do código ao salvar ([dart format]);
    • seleção do dispositivo, no canto inferior direito da janela (ou o comando “Flutter: Select Device”);
    • execução com F5 (depuração: pontos de interrupção, variáveis); a cada vez que um arquivo é salvo, o aplicativo é recarregado na hora;
    • ações sobre widgets (Ctrl-. em um widget): “Wrap with Padding”, “Wrap with Column”, “Extract Widget” etc., muito úteis para reorganizar uma árvore de widgets.

    Para executar um exemplo com F5, abra seu arquivo [main.dart] antes de pressionar F5 (ou crie um arquivo chamado [.vscode/launch.json]). Abra um projeto pelo menu File / Open Folder (a pasta [examples_flutter], por exemplo) e abra um console pelo menu Terminal / New Terminal.

    14.4. A ferramenta Flutter DevTools

    O [Flutter DevTools] está incluído no SDK. Enquanto a aplicação está em execução, [flutter run] exibe seu endereço (“The Flutter DevTools debugger and profiler... is available at: http://127.0.0.1:9101... ”); no [VS Code], o comando “Flutter: Open DevTools” o abre no editor. Suas abas mais úteis:

    • “Flutter Inspector”: a árvore de widgets da tela e as propriedades de cada widget. “Select Widget Mode” permite tocar em um elemento no celular para encontrar seu widget na árvore; “Show Guidelines” desenha as margens e as linhas de alinhamento. É a ferramenta que responde à pergunta “Por que este widget não está no lugar certo?”;
    • “Performance” e “CPU Profiler”: o tempo gasto para renderizar e desenhar cada quadro, para identificar a causa de uma animação travando;
    • “Network”: as requisições HTTP da aplicação, incluindo seus cabeçalhos e corpos; aqui você vê o cookie do token sendo enviado e devolvido;
    • “Logging”: o que a aplicação exibe ([debugPrint]).

    14.5. Instalação do Node.js

    O [Node.js] é baixado em nodejs.org: selecione a versão LTS (suporte de longo prazo). O instalador para [Windows] também instala o [npm]. Ele só é necessário para o servidor JSON. Verifique a instalação em um console:

    1
2
    node --version
npm --version

    14.6. Instalação do MySQL com o Laragon

    O servidor JSON exige o [MySQL] (ou o [MariaDB]). O [Laragon] (laragon.org) instala um deles no [Windows], pronto para uso, com a ferramenta de administração [HeidiSQL]. Após a instalação:

    • o botão “Start All” inicia o servidor [MySQL] na porta 3306;
    • o usuário [root] não tem senha: esses são os valores padrão do arquivo [.env.example] do servidor;
    • no [HeidiSQL] (o botão “Database”), o item de menu File / Run SQL File executa o script [database/dbrdvmedecins2.sql].

    No [Linux] ou no [macOS], instale o [MySQL] ou o [MariaDB] usando o gerenciador de pacotes do sistema e execute o script com o cliente de linha de comando: [mysql -u root -p < database/dbrdvmedecins2.sql].

    14.7. Instalação do curl

    O [curl] já vem incluído no [Windows] versões 10 e 11, [macOS] e na maioria das distribuições [Linux]. Verifique sua versão:

    1
    curl --version

    A opção [--json], usada neste documento, está disponível desde a versão 7.82 (2022). Se você usa uma versão mais antiga, substitua [--json @file] por [-H "Content-Type: application/json" -d @file] ou instale uma versão recente em curl.se.

    No [PowerShell], você deve digitar [curl.exe], e não [curl]: no [PowerShell], [curl] é um alias de outro comando ([Invoke-WebRequest]), que não inclui as opções do [curl]. O prompt de comando ([cmd]) não tem esse problema.
