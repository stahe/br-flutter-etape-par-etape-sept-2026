    1.1. O papel do Flutter em um aplicativo cliente/servidor

    O aplicativo tem duas partes, que se comunicam entre si apenas por meio de requisições HTTP:

    • 1: O aplicativo [Flutter], executado no celular, envia uma requisição HTTP ao servidor, por exemplo, [GET /api/schedule?doctorId=1&day=2026-10-05];
    • 2: O servidor responde com dados JSON: a agenda desse médico naquele dia. Ele não gera nenhuma página;
    • 3: Com esses dados, o [Flutter] atualiza a tela do celular.

    Esta é exatamente a arquitetura dos clientes [React], [Vue.js] e [Angular]: a única diferença é o que gera a exibição. Enquanto um navegador constrói uma página a partir de HTML e CSS, o [Flutter] desenha cada pixel da tela por conta própria, usando seu próprio motor gráfico. Ele não usa os componentes do sistema (os botões do [Android] ou do [iOS]): ele os imita ou fornece os seus próprios. É isso que lhe permite exibir o mesmo aplicativo, pixel a pixel, em um celular [Android], em um [iPhone], em um navegador ou em um computador.

    [Flutter] é um framework criado pelo [Google] e lançado em 2018. Atualmente é o framework mais usado para escrever aplicativos mobile para [Android] e [iOS] a partir de uma única base de código. Ele se baseia em três conceitos centrais:

    • tudo é um widget: a tela é descrita por uma árvore de widgets, objetos que representam cada um uma parte da interface — como um texto, um botão, uma margem, uma coluna ou uma tela inteira. Você cria seus próprios widgets combinando os fornecidos pelo [Flutter];
    • a interface é uma função do estado: um widget tem um método [build()] que descreve o que exibir com base em seus dados. Quando os dados mudam ([setState()]), o [Flutter] chama [build()], compara a nova árvore com a antiga e redesenha o que mudou. Nunca escrevemos código que modifica a tela: descrevemos a tela com base em seu estado. Os leitores do curso de [React] reconhecerão esse princípio: é o mesmo dos componentes e do [useState];
    • uma linguagem, [Dart], compilada em código de máquina para o celular (resultando em aplicativos rápidos), ou em [JavaScript] ou [WebAssembly] para o navegador. Durante o desenvolvimento, o [Dart] permite o hot reload: uma alteração no código é aplicada ao aplicativo em execução em um segundo, sem perder seu estado.

    Assim como o [React], o [Flutter] não é um framework “completo” para a comunicação com um servidor: o cliente HTTP, o roteador, o estado compartilhado e as traduções são fornecidos por pacotes (bibliotecas) publicados no site pub.dev. Este curso usa os pacotes recomendados na documentação do [Flutter] e mantidos, em sua maioria, pela própria equipe do [Flutter]: [http] (requisições HTTP), [go_router] (o roteador), [provider] (estado compartilhado), [shared_preferences] (armazenamento no dispositivo), [intl] (datas e números em cada idioma), [flutter_svg] (imagens SVG).

    1.2. Ferramentas utilizadas

    Os exemplos foram escritos e testados com as seguintes ferramentas (sua instalação é descrita no apêndice):

    • o SDK do [Flutter] 3.44, que inclui o SDK do [Dart] 3.12;
    • o editor [Visual Studio Code] e sua extensão [Flutter] (que também instala a extensão [Dart]);
    • [Android Studio], apenas pelo seu gerenciador de emuladores, e o SDK do [Android]: um emulador [Android] (um celular simulado no computador) ou um celular [Android] real conectado ao computador;
    • o navegador [Chrome], para a versão web dos aplicativos;
    • o SGBD [MySQL] (ou [MariaDB]), por exemplo, o do [Laragon] no [Windows] , e o [Node.js]: eles são exigidos pelo servidor JSON, como descrito no capítulo que o apresenta;
    • a ferramenta de linha de comando [curl], que exibe as respostas HTTP brutas.

    Os pacotes usados são os dos arquivos [pubspec.yaml]: [go_router] 16, [provider] 6, [http] 1.5, [shared_preferences] 2.5, [flutter_svg] 2, [intl], e os pacotes [flutter_localizations] e [flutter_test] incluídos no [Flutter].

    1.3. Capturas de tela

    As capturas de tela deste documento foram geradas automaticamente por testes do [Flutter] (pastas [test/captures] dos projetos): cada teste inicia um exemplo, interage com ele como um usuário faria (digitando texto, tocando em botões) e, em seguida, instrui o motor do [Flutter] a renderizar a tela como um arquivo de imagem na resolução de um celular [Android] (1080 x 2340 pixels). São, portanto, telas reais do aplicativo, renderizadas pelo mesmo motor que roda no celular; os únicos elementos ausentes são a barra de status do celular (hora, bateria) e o teclado na tela. O capítulo do primeiro exemplo mostra o mesmo aplicativo em execução em um emulador [Android].

    As pastas específicas de cada plataforma ([android/], [web/], [windows/]) não são fornecidas por inteiro: são pequenos projetos — [Android] (web) e [Windows] — que o [Flutter] pode gerar e que dependem da versão do [Flutter] instalada. Você os gera uma vez e depois baixa os pacotes em um console aberto na pasta [examples_flutter] (no [VS Code]: menu Terminal / Novo Terminal):

    1
2
    flutter create --platforms=android,web,windows --org fr.stahe --project-name examples_flutter .
flutter pub get

    [flutter create .] (o ponto indica a pasta atual) completa o projeto sem modificar os arquivos existentes: o arquivo [android/app/src/main/AndroidManifest.xml] fornecido (veja o Exemplo 22) é preservado. Se você pular essa etapa, o comando [flutter run] falha em um celular com uma mensagem enganosa: “Build failed due to use of deleted Android v1 embedding” (o [Flutter] não encontra o projeto [Android] e presume que ele é muito antigo).

    Em seguida, execute um exemplo especificando o arquivo [main.dart] com a opção [-t] (de “target”):

    1
    flutter run -t lib/ex01_first_application/main.dart

    O comando [flutter run] pergunta em qual dispositivo executar o aplicativo se encontrar vários (um emulador [Android], o [Chrome], o [Windows]...). Você pode especificá-lo com a opção [-d] (de “device”):

    1
2
    flutter run -d emulator-5554 -t lib/ex01_first_application/main.dart
flutter run -d chrome -t lib/ex01_first_application/main.dart

    Enquanto o aplicativo está em execução, o console aceita alguns comandos de uma letra: r (hot reload: as alterações no código são aplicadas e o estado é preservado), R (hot restart: o aplicativo reinicia do zero), q (parar). No [VS Code], você também pode abrir o arquivo do exemplo [main.dart] e pressionar F5; o dispositivo é então selecionado na barra de status, no canto inferior direito da janela.

    Os exemplos 22 a 25 consultam os servidores JSON e [RdvMedecins]: você precisará tê-los instalados e em execução, conforme explicado no capítulo dedicado a eles.
