    12. Implantação

    Durante o desenvolvimento, a aplicação roda sob o controle do [flutter run]: em modo “debug”, que é mais lento, com hot reload e verificações ([assert]) feitas pelo [Flutter]. Para implantá-la, fazemos o build em modo “release”: código otimizado, sem ferramentas de desenvolvimento. Geramos uma versão por plataforma.

    12.1. A versão web

    1. Gere o build do cliente. Na pasta [rdvmedecins_flutter]:
    1
    flutter build web --no-web-resources-cdn

    O console exibe:

    Dois avisos, sem consequências: a compilação para [WebAssembly] seria possível (veja abaixo); uma biblioteca do [Flutter] faz referência a ícones do estilo [iOS] ([CupertinoIcons]), que a aplicação não usa.

    O compilador [dart2js] compilou toda a aplicação ([Dart], [Flutter] e os pacotes) para [JavaScript], na pasta [build/web/]:

    • [index.html]: A página da aplicação, que carrega [flutter_bootstrap.js], depois [main.dart.js] (3,5 MB, cerca de 1 MB depois de comprimido pelo servidor): o NOSSO código, junto com todo o código do [Flutter] e dos pacotes, otimizado. [Flutter] não gera HTML: a aplicação desenha cada pixel por conta própria em um canvas, usando o mesmo engine do celular;
    • [canvaskit/]: esse engine de renderização ([Skia], compilado para [WebAssembly]: [canvaskit.wasm], 7 MB). Sem a opção [--no-web-resources-cdn], ele seria baixado de um servidor do [Google]; com ela, é incluído na aplicação, que deixa de depender de qualquer site externo;
    • [assets/]: os recursos do [pubspec.yaml] (dicionários, fontes). Os ícones passam por “tree-shaking”: apenas os usados pela aplicação são mantidos na fonte de ícones;
    • No primeiro carregamento, o navegador baixa alguns megabytes (principalmente o engine de renderização) e depois os guarda em cache. Esse é o principal ponto fraco do [Flutter] para a web: ele é mais adequado a aplicações (que são abertas e usadas por longos períodos) do que a sites (que são navegados rapidamente).

    A opção [--wasm] compila a aplicação para [WebAssembly] em vez de [JavaScript]: é mais rápida nos navegadores que a suportam (versões recentes do [Chrome], do [Edge] e do [Firefox]); os outros navegadores recebem automaticamente a versão [JavaScript].

    1. Coloque-o no servidor. Copie o CONTEÚDO da pasta [build/web/] para uma pasta chamada [client/] na raiz do servidor JSON ([rdvmedecins-nestjs-json/client/index.html], [rdvmedecins-nestjs-json/client/main.dart.js]...) e reinicie o servidor. Ele exibe:
    1
2
    [Nest] LOG [RdvMedecins] web client served from .../rdvmedecins-nestjs-json/client
[Nest] LOG [RdvMedecins] JSON server started: http://localhost:8080/api

    A aplicação completa agora está disponível em http://localhost:8080. O servidor serve os arquivos do cliente e devolve [index.html] para qualquer outro endereço fora de /api: recarregar a página /schedule funciona (é o roteador do cliente que a exibe). O arquivo [src/web/client-spa.ts] do servidor cuida dessa tarefa. A aplicação é servida pelo servidor da API: o endereço relativo de [config.dart] ([''], ou [/api/...]) está correto.

    Você também pode experimentar a versão gerada sem o servidor JSON, usando qualquer servidor de arquivos, mas as requisições a /api falharão.

    12.2. A versão Android

    1. Gere o build do aplicativo, especificando o endereço do servidor:
    1
    flutter build apk --dart-define=SERVER=http://192.168.1.20:8080

    O console exibe (para um APK gerado sem [--dart-define]):

    1
2
3
4
    Running Gradle task 'assembleRelease'...
Font asset "MaterialIcons-Regular.otf" was tree-shaken, reducing it from 1645184 to 3400 bytes (99.8% reduction). Tree-shaking can be disabled by providing the --no-tree-shake-icons flag when building your app.
Running Gradle task 'assembleRelease'...                          193,4s
√ Built build\app\outputs\flutter-apk\app-release.apk (53.5MB)

    (Alguns avisos relativos ao [Gradle] e ao [Java], que não tiveram impacto, foram removidos.) O primeiro build demora bastante: o [Gradle] baixa suas próprias ferramentas e bibliotecas; os builds seguintes são muito mais rápidos.

    O compilador [Dart] traduziu a aplicação em código de máquina para as três famílias de processadores dos celulares [Android] (ARM de 32 bits, ARM de 64 bits, x86 de 64 bits), e a ferramenta de build do [Android] ([Gradle]) a empacotou, junto com o engine do [Flutter], em um arquivo APK: o formato de instalação de aplicativos do [Android]. Ele contém três cópias da aplicação e de seu engine, uma por família de processadores, o que explica seu tamanho. [--split-per-abi] geraria três arquivos APK menores, um por família de processadores; um “App Bundle” (veja abaixo) permite que a loja entregue apenas o que cada celular precisa.

    1. Instale-o. Com o celular conectado ao computador (cabo USB, depuração USB habilitada):
    1
    flutter install

    Você também pode copiar o arquivo APK para o celular e abri-lo: o [Android] pedirá então que você permita a instalação de aplicativos “de fontes desconhecidas”.

    1. Para uma versão de produção de verdade:
    • o aplicativo deve ser assinado com uma chave específica do desenvolvedor: o projeto gerado por [flutter create] assina a versão “release” com a chave de depuração, o que basta para testes, mas não para uma loja. A documentação do [Flutter] (“Build and release an Android app”) descreve como criar a chave e configurar o [Gradle];
    • [Google Play Store] espera um “Android App Bundle” em vez de um APK: [flutter build appbundle];
    • O nome e o ícone do aplicativo são configurados em [android/app/src/main/AndroidManifest.xml] ([android:label]) e em [android/app/src/main/res/mipmap-*/];
    • O servidor deve ser configurado para HTTPS (as senhas trafegam), e a linha [android:usesCleartextTraffic="true"] é removida do manifest.

    12.3. O servidor de produção

    Em produção de verdade, não se esqueça do arquivo [.env] no servidor:

    • um [JWT_SECRET]longo e aleatório;
    • um [CAPTCHA_TEST]vazio;
    • [COOKIE_SECURE=true] se o site for servido via HTTPS (e deve ser). O cliente mobile envia o cookie independentemente dessa opção: é o navegador que a impõe;
    • [TRUST_PROXY=true] se o servidor estiver atrás de um proxy ([nginx]...), para que o limite de tentativas veja o endereço IP real dos clientes.

    Em seguida, iniciamos o servidor compilado: [npm run build], seguido de [npm run start:prod].
