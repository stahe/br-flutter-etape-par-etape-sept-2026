    4. Widgets

    Escrever seus próprios widgets está no cerne do trabalho com o [Flutter]: uma tela bem escrita é composta de pequenos widgets, cada um com seus parâmetros, seu [build] e, se necessário, seu estado. Este capítulo mostra como eles se comunicam entre si (parâmetros, funções), como são montados (composição), como funcionam (ciclo de vida), como compartilham dados sem repassá-los de um a outro (dados herdados) e como reutilizar comportamento.

  final String title;
  final String firstName;
  final String lastName;

// lib/ex10_widget_parameters/doctor_card.dart - um widget FILHO
// -------------------------------------------------------------------------
// Ele recebe seus dados do pai por meio dos PARÂMETROS do seu
// construtor, guardados em campos final. Seu tipo é verificado em
// tempo de compilação: DoctorCard(doctor: 42) seria recusado.
//   - required: o pai DEVE fornecer este parâmetro;
//   - this.compact = false: um parâmetro opcional, com seu valor padrão.
//
// Regra de ouro: um widget NUNCA MODIFICA seus parâmetros (eles são final).
// Os dados descem do pai para o filho; para pedir uma
// alteração, o filho chama uma função que o pai lhe passou
// (veja o exemplo 11). Quando o pai altera seus dados, ele RECONSTRÓI seus
// filhos com novos parâmetros.
// =========================================================================

import 'package:flutter/material.dart';

import 'doctor.dart';

// o "estilo" do card: constantes PRIVADAS deste arquivo (o "_").
// Nenhum outro widget pode vê-las, nem ser incomodado por elas
const _initialsColor = Color(0xFF087EA4);
const _initialsStyle = TextStyle(color: Colors.white, fontWeight: FontWeight.bold);

class DoctorCard extends StatelessWidget {
  final Doctor doctor;
  final int rank;
  final bool compact;

  // const: se todos os parâmetros são constantes, o widget também é
  // (o Flutter então nem precisa reconstruí-lo)
  const DoctorCard({super.key, required this.doctor, required this.rank, this.compact = false});

  @override
  Widget build(BuildContext context) {
    // um valor calculado a partir dos parâmetros
    final initials = '${doctor.firstName[0]}${doctor.lastName[0]}';

    return Card(
      // uma borda verde para um médico disponível
      shape: RoundedRectangleBorder(
        borderRadius: BorderRadius.circular(12),
        side: doctor.available ? const BorderSide(color: Colors.green, width: 2) : BorderSide.none,
      ),
      child: Padding(
        padding: const EdgeInsets.all(12),
        child: Row(
          children: [
            CircleAvatar(
              backgroundColor: _initialsColor,
              child: Text(initials, style: _initialsStyle),
            ),
            const SizedBox(width: 12),
            // Expanded: o texto ocupa toda a largura restante
            Expanded(
              child: Column(
                crossAxisAlignment: CrossAxisAlignment.start,
                children: [
                  Text(
                    '$rank. ${doctor.title} ${doctor.firstName} ${doctor.lastName}',
                    style: Theme.of(context).textTheme.titleMedium,
                  ),
                  if (!compact) Text(doctor.specialty, style: const TextStyle(color: Colors.grey)),
                ],
              ),
            ),
          ],
        ),
      ),
    );
  }
}
    • linhas 23–24: o “estilo” do card: constantes privadas a este arquivo (o “_”). Nenhum outro arquivo pode vê-las nem ser afetado por elas. É o equivalente, no [Flutter], dos “módulos CSS” do [React]: não há folha de estilo global; o estilo de um widget fica embutido em seu código;
    • linhas 27–29: os parâmetros do widget, guardados em campos [final];
    • linha 33: o construtor. [required this.doctor]: um parâmetro obrigatório, guardado diretamente no campo; [this.compact = false]: um parâmetro opcional, com seu valor padrão. O construtor é [const]: se todos os argumentos forem constantes, o card também será constante;
    • linha 38: um valor calculado a partir dos parâmetros;
    • linhas 42–44: a forma do card ([Card]): cantos arredondados e uma borda verde se o médico estiver disponível ([BorderSide.none] caso contrário);
    • linhas 50–52: um disco colorido com as iniciais;
    • linha 64: a especialidade só é exibida na visualização não compacta.

    Regra de ouro: um widget nunca modifica seus próprios parâmetros (eles são [final]; aliás, o compilador proíbe isso). Os dados fluem do pai para o filho; para solicitar uma mudança, o filho chama uma função que o pai lhe passou (exemplo 11). Quando o pai muda seus dados, ele reconstrói seus filhos com novos parâmetros.

// lib/ex10_widget_parameters/main.dart - o widget PAI
// -------------------------------------------------------------------------
// Ele importa o widget DoctorCard e o usa, quantas vezes for
// necessário, como qualquer widget do Flutter: um widget é um pedaço
// de interface REUTILIZÁVEL, com seus próprios parâmetros, seu build() e
// seu estilo. Escrever seus próprios widgets é o coração do trabalho com o
// Flutter: uma tela bem escrita é feita de pequenos widgets.
// =========================================================================

import 'package:flutter/material.dart';

import 'doctor_card.dart';
import 'doctor.dart';

void main() {
  runApp(
    MaterialApp(
      debugShowCheckedModeBanner: false,
      theme: ThemeData(colorSchemeSeed: Colors.indigo),
      home: const DoctorsPage(),
    ),
  );
}

class DoctorsPage extends StatefulWidget {
  const DoctorsPage({super.key});

  @override
  State<DoctorsPage> createState() => _DoctorsPageState();
}

class _DoctorsPageState extends State<DoctorsPage> {
  List<Doctor> _doctors = const [
    Doctor(id: 1, title: 'Mme', firstName: 'Marie', lastName: 'PELISSIER', specialty: 'general practitioner', available: true),
    Doctor(id: 2, title: 'Mr', firstName: 'Paul', lastName: 'TATOU', specialty: 'pediatrician', available: false),
    Doctor(id: 3, title: 'Melle', firstName: 'Sophie', lastName: 'DUPONT', specialty: 'general practitioner', available: true),
  ];
  bool _compact = false;

  // o pai altera SEUS dados: o Flutter chama seu build() de novo, que
  // reconstrói os filhos com seus novos parâmetros
  void _toggleAvailability() {
    setState(() {
      _doctors = [for (final m in _doctors) m.withAvailability(!m.available)];
    });
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Example 10 - the widgets and their parameters')),
      body: ListView(
        padding: const EdgeInsets.all(16),
        children: [
          SwitchListTile(
            contentPadding: EdgeInsets.zero,
            title: const Text('compact display'),
            value: _compact,
            onChanged: (v) => setState(() => _compact = v),
          ),
          Align(
            alignment: Alignment.centerLeft,
            child: OutlinedButton(onPressed: _toggleAvailability, child: const Text('Toggle the availabilities')),
          ),
          const SizedBox(height: 8),
          for (final (i, m) in _doctors.indexed)
            // cada card recebe SEUS parâmetros
            DoctorCard(key: ValueKey(m.id), doctor: m, rank: i + 1, compact: _compact),
          const SizedBox(height: 16),
          const Text(
            'The same card, in its compact version, by setting the parameter:',
            style: TextStyle(color: Colors.grey),
          ),
          SizedBox(width: 260, child: DoctorCard(doctor: _doctors[0], rank: 1, compact: true)),
        ],
      ),
    );
  }
}
    • linhas 34–39: o estado do pai: a lista de médicos (uma lista constante, que será substituída por outra) e a exibição compacta;
    • linhas 43–45: o pai altera SEUS dados para uma nova lista formada por cópias dos médicos. [Flutter] chama seu [build], que reconstrói os cards com seus novos parâmetros;
    • linha 69: um card por médico, com SEUS parâmetros. O widget [DoctorCard] é usado exatamente como um widget do [Flutter];
    • linha 75: o mesmo card, em versão compacta, em uma caixa de 260 pontos de largura.

    // =========================================================================
// lib/ex11_lifting_state_up/counter.dart
// -------------------------------------------------------------------------
// Um filho que NOTIFICA seu pai: o pai lhe passa FUNÇÕES como
// parâmetros (por convenção, seus nomes começam com "on"), e o filho
// as chama quando algo acontece:
//     Counter(label: 'Coffees', max: 3, onIncrement: ..., onLimit: ...)
// Os tipos dessas funções têm nomes prontos no Flutter:
//   - ValueChanged<int> : uma função que recebe um int e não retorna nada;
//   - VoidCallback      : uma função sem parâmetros, que não retorna nada.
// =========================================================================

import 'package:flutter/material.dart';

class Counter extends StatefulWidget {
  final String label;
  final int max;
  final ValueChanged<int> onIncrement; // com o novo valor
  final VoidCallback onLimit; // sem dados

  const Counter({
    super.key,
    required this.label,
    required this.max,
    required this.onIncrement,
    required this.onLimit,
  });

  @override
  State<Counter> createState() => _CounterState();
}

class _CounterState extends State<Counter> {
  // o estado ESPECÍFICO deste contador: cada Counter tem o seu
  int _value = 0;

  void _plus() {
    // widget: no objeto State, dá acesso aos parâmetros do widget
    if (_value >= widget.max) {
      widget.onLimit();
      return;
    }
    setState(() => _value++);
    // o pai é NOTIFICADO e recebe o novo valor
    widget.onIncrement(_value);
  }

  @override
  Widget build(BuildContext context) {
    return Row(
      children: [
        SizedBox(width: 110, child: Text(widget.label)),
        OutlinedButton(onPressed: _plus, child: const Text('+1')),
        const SizedBox(width: 12),
        Chip(label: Text('$_value / ${widget.max}')),
      ],
    );
  }
}
    • linhas 18–19: dois parâmetros que são funções, as quais o contador chamará. [ValueChanged<int>] é o tipo de uma função que recebe um [int] e não devolve nada; [VoidCallback] é o tipo de uma função sem parâmetros. Por convenção, seus nomes começam com “on”, como [onPressed] ou [onChanged] nos widgets do [Flutter];
    • linha 35: o estado ESPECÍFICO deste contador: cada [Counter] tem o seu;
    • linhas 37–45: dentro do objeto [State], [widget] dá acesso aos parâmetros do widget: [widget.max], [widget.onLimit]... Se o máximo for ultrapassado, o contador notifica seu pai ([widget.onLimit()]); caso contrário, altera seu estado e depois notifica o pai transmitindo o novo valor. Ao contrário do [React], o estado é atualizado imediatamente: [_value] já tem seu novo valor quando ele é transmitido.

    // =========================================================================
// lib/ex11_lifting_state_up/labeled_text_field.dart - um widget CONTROLADO
// -------------------------------------------------------------------------
// Um campo de formulário "caseiro" (rótulo + campo + ajuda + contador de
// caracteres) que é usado como um campo controlado:
//     LabeledTextField(value: _name, onChanged: (v) => setState(() => _name = v), ...)
// O valor pertence ao PAI, que o passa (value) e que é
// notificado a cada tecla (onChanged). Quem decide é o pai.
//
// Uma dificuldade específica do Flutter: um TextField guarda seu texto em um
// controller, que precisa sobreviver às reconstruções. O widget portanto tem um
// estado (o controller)... que ele deve manter ATUALIZADO quando o pai altera
// o valor (botão "Clear"): esse é o papel de didUpdateWidget.
// =========================================================================

import 'package:flutter/material.dart';

class LabeledTextField extends StatefulWidget {
  final String value;
  final ValueChanged<String> onChanged;
  final String label;
  final int max;
  final String help;

  const LabeledTextField({
    super.key,
    required this.value,
    required this.onChanged,
    required this.label,
    required this.max,
    this.help = '',
  });

  @override
  State<LabeledTextField> createState() => _LabeledTextFieldState();
}

class _LabeledTextFieldState extends State<LabeledTextField> {
  // late: o campo será inicializado mais tarde (em initState), antes de qualquer uso
  late final TextEditingController _controller;

  @override
  void initState() {
    super.initState();
    _controller = TextEditingController(text: widget.value);
  }

  // chamado quando o PAI reconstrói este widget com novos parâmetros;
  // oldWidget: o widget anterior, para comparar
  @override
  void didUpdateWidget(LabeledTextField oldWidget) {
    super.didUpdateWidget(oldWidget);
    if (widget.value != _controller.text) {
      _controller.text = widget.value; // o pai alterou o valor por conta própria
    }
  }

  @override
  void dispose() {
    _controller.dispose();
    super.dispose();
  }

  @override
  Widget build(BuildContext context) {
    final full = widget.value.length == widget.max;
    return TextField(
      controller: _controller,
      maxLength: widget.max, // o campo recusa os caracteres excedentes
      decoration: InputDecoration(
        labelText: widget.label,
        helperText: widget.help,
        // a borda fica vermelha quando o campo está cheio
        errorText: full ? 'Maximum length reached' : null,
      ),
      onChanged: widget.onChanged, // a função do pai, passada como está
    );
  }
}

    Um campo de formulário “personalizado” (rótulo + campo + tooltip + contador de caracteres) que funciona como um campo controlado: o valor pertence ao pai, que o passa ao campo ([value]) e é notificado a cada tecla digitada ([onChanged]).

    • Linha 40: [late]: este campo será inicializado mais tarde (em [initState]), mas antes de ser usado. O [Dart] verifica isso em tempo de execução;
    • Linhas 43–45: o controller começa com o valor do pai;
    • linhas 51–54: este é o desafio específico do [Flutter]: um [TextField] guarda seu texto em um controller, que deve sobreviver às reconstruções da página. O widget, portanto, tem um estado (o controller)... que ele deve manter atualizado quando o próprio pai altera o valor (botão Limpar). [didUpdateWidget] é chamado toda vez que o pai reconstrói este widget com novos parâmetros; ele recebe o widget antigo para comparação. Se o valor do pai for diferente do texto do campo, ele é copiado;
    • linha 69: o campo rejeita os caracteres excedentes e exibe um contador (“12/20”);
    • linha 72: uma tooltip aparece abaixo do campo;
    • linha 74: a borda fica vermelha quando o campo está cheio;
    • linha 76: a função do pai, passada como está ao [TextField].

class ParentPage extends StatefulWidget {
  const ParentPage({super.key});

  @override
  State<ParentPage> createState() => _ParentPageState();
}

class _ParentPageState extends State<ParentPage> {
  int _total = 0;
  String _message = '';
  String _firstName = 'Marie';
  String _lastName = 'PELISSIER';

  // a função chamada por um contador: ela recebe o valor que o contador passa
  void _onIncrement(String label, int value) {
    setState(() {
      _total++;
      _message = '$label is now $value';
    });
  }

  void _clear() {
    setState(() {
      _firstName = '';
      _lastName = '';
    });
  }

  @override
  Widget build(BuildContext context) {
    final titleStyle = Theme.of(context).textTheme.titleSmall;
    return Scaffold(
      appBar: AppBar(title: const Text('Example 11 - the child notifies its parent')),
      body: ListView(
        padding: const EdgeInsets.all(16),
        children: [
          Card(
            child: Padding(
              padding: const EdgeInsets.all(12),
              child: Column(
                crossAxisAlignment: CrossAxisAlignment.start,
                children: [
                  Text('1. Functions called by the children', style: titleStyle),
                  Counter(
                    label: 'Coffees',
                    max: 3,
                    onIncrement: (v) => _onIncrement('Coffees', v),
                    onLimit: () => setState(() => _message = 'No more than 3 coffees!'),
                  ),
                  Counter(
                    label: 'Glasses of water',
                    max: 8,
                    onIncrement: (v) => _onIncrement('Glasses of water', v),
                    onLimit: () => setState(() => _message = 'Enough drinking.'),

// SimpleTable<T> é um widget genérico: ele exibe linhas de qualquer

import 'package:flutter/material.dart';

// o tipo de uma função que constrói as células de uma linha
typedef CellsBuilder<T> = List<Widget> Function(T row, int index);

class SimpleTable<T> extends StatelessWidget {
  final List<T> rows;
  final List<String> columns;
  final CellsBuilder<T> cells;
  final Widget empty; // exibido quando não há nenhuma linha

  const SimpleTable({
    super.key,
    required this.rows,
    required this.columns,
    required this.cells,
    this.empty = const Text('No data.'),
  });

  // uma célula: uma pequena margem ao redor do seu conteúdo
  static Widget _cell(Widget content) => Padding(padding: const EdgeInsets.all(6), child: content);

  @override
  Widget build(BuildContext context) {
    if (rows.isEmpty) {
      return Column(
        crossAxisAlignment: CrossAxisAlignment.start,
        children: [
          Text(columns.join('   '), style: const TextStyle(fontWeight: FontWeight.bold)),
          const Divider(),
          DefaultTextStyle.merge(
            style: const TextStyle(color: Colors.grey),
            child: empty,
          ),
        ],
      );
    }
    return Table(
      defaultVerticalAlignment: TableCellVerticalAlignment.middle,
      border: TableBorder(horizontalInside: BorderSide(color: Colors.grey.shade300)),
      children: [
        TableRow(
          children: [for (final c in columns) _cell(Text(c, style: const TextStyle(fontWeight: FontWeight.bold)))],
        ),
        for (final (i, row) in rows.indexed)
          // as células DESTA linha, construídas pela função do pai
          TableRow(children: [for (final c in cells(row, i)) _cell(c)]),
      ],
    );
  }
}

// lib/ex13_lifecycle/clock.dart - um widget que inicia e para
// -------------------------------------------------------------------------
// A vida do objeto State de um StatefulWidget:
//   1. initState()              : ele acabou de ser criado, o widget está prestes a
//                                 aparecer. O que deve ser iniciado é iniciado aqui;
//   2. didChangeDependencies()  : logo depois, e depois a cada vez que um dado herdado
//                                 que ele lê muda (veja o exemplo 14);
//   3. build()                  : quantas vezes for necessário;
//   4. didUpdateWidget(old)     : o pai o reconstruiu com novos
//                                 parâmetros;
//   5. dispose()                : o widget desaparece de vez. O que
//                                 foi iniciado é PARADO aqui.
// Um relógio dispara um timer (Timer.periodic) quando aparece...
// e deve obrigatoriamente pará-lo quando desaparece: senão o
// timer continuaria rodando à toa e chamaria setState()
// em um objeto morto (um erro).
// =========================================================================

import 'dart:async';

import 'package:flutter/material.dart';

String currentTime() => DateTime.now().toString().substring(11, 19); // "12:05:09"

class Clock extends StatefulWidget {
  final ValueChanged<String> onLog;
  final Color color;

  const Clock({super.key, required this.onLog, this.color = Colors.indigo});

  @override
  State<Clock> createState() => _ClockState();
}

class _ClockState extends State<Clock> {
  String _time = currentTime();
  // late: inicializado em initState
  late final Timer _timer;

  // notificando o pai... DEPOIS da construção da tela atual: não
  // modificamos o estado de um widget (o pai) enquanto ele está sendo construído
  void _log(String message) {
    WidgetsBinding.instance.addPostFrameCallback((_) => widget.onLog(message));
  }

  @override
  void initState() {
    super.initState(); // sempre primeiro
    _log('Clock: initState - starting the timer');
    _timer = Timer.periodic(const Duration(seconds: 1), (_) {
      setState(() => _time = currentTime());
    });
  }

  @override
  void didUpdateWidget(Clock oldWidget) {
    super.didUpdateWidget(oldWidget);
    if (oldWidget.color != widget.color) {
      _log('Clock: didUpdateWidget - new color');
    }
  }

  @override
  void dispose() {
    _timer.cancel(); // a LIMPEZA
    _log('Clock: dispose - timer stopped');
    super.dispose(); // sempre por último
  }

  @override
  Widget build(BuildContext context) {
    return Text(
      _time,
      style: TextStyle(fontSize: 40, fontFamily: 'RobotoMono', color: widget.color),
    );
  }
}

    didUpdateWidget(old)

    dispose()

// -------------------------------------------------------------------------
// Como compartilhar dados e funções entre widgets
// distantes, sem passá-los de parâmetro em parâmetro por todos os
// intermediários? Com um InheritedWidget, um dado "herdado":
//   1. um widget PROVIDER, colocado no alto da árvore, carrega o dado;
//   2. qualquer descendente, em qualquer profundidade, o LÊ
//      com context.dependOnInheritedWidgetOfExactType<Provider>();
//   3. o descendente que o leu fica então INSCRITO: ele é reconstruído
//      quando o dado muda.
// É o mecanismo que o próprio Flutter usa: Theme.of(context),
// MediaQuery.of(context), Navigator.of(context)... são leituras de
// dados herdados.
//
// InheritedNotifier é uma variante pronta: o dado é um objeto
// que NOTIFICA suas alterações (um ChangeNotifier, que chama
// notifyListeners()), e o provider então reconstrói seus leitores.
// A convenção: um método estático of(context) para ler o dado.
// =========================================================================

import 'package:flutter/material.dart';

// o dado: um ChangeNotifier. notifyListeners() notifica seus inscritos
class Log extends ChangeNotifier {
  final List<String> lines = [];

  void trace(String message) {
    lines.insert(0, '${DateTime.now().toString().substring(11, 19)} $message');
    if (lines.length > 6) lines.removeLast();
    notifyListeners();
  }
}

// o provider: ele carrega o log e reconstrói seus leitores quando
// o log notifica uma alteração
class LogProvider extends InheritedNotifier<Log> {
  const LogProvider({super.key, required Log log, required super.child}) : super(notifier: log);

  // a leitura: o provider MAIS PRÓXIMO acima de context
  static Log of(BuildContext context) {
    final provider = context.dependOnInheritedWidgetOfExactType<LogProvider>();
    if (provider == null) {
      throw FlutterError('LogProvider.of: no LogProvider above this widget');
    }
    return provider.notifier!;
  }
}

import 'dart:async';

import 'package:flutter/material.dart';

class ClockProvider extends StatefulWidget {
  final Duration period;
  final Widget child;

  const ClockProvider({super.key, this.period = const Duration(seconds: 1), required this.child});

  // o valor padrão: uma data congelada, lida por um widget sem provider
  static DateTime of(BuildContext context) =>
      context.dependOnInheritedWidgetOfExactType<_InheritedClock>()?.now ?? DateTime(2026);

  @override
  State<ClockProvider> createState() => _ClockProviderState();
}

class _ClockProviderState extends State<ClockProvider> {
  DateTime _now = DateTime.now();
  Timer? _timer;

  void _start() {
    _timer?.cancel();
    _timer = Timer.periodic(widget.period, (_) => setState(() => _now = DateTime.now()));
  }

  @override
  void initState() {
    super.initState();
    _start();
  }

  // se o pai altera o período, o timer é reiniciado
  @override
  void didUpdateWidget(ClockProvider oldWidget) {
    super.didUpdateWidget(oldWidget);
    if (oldWidget.period != widget.period) _start();
  }

  @override
  void dispose() {
    _timer?.cancel();
    super.dispose();
  }

  @override
  Widget build(BuildContext context) => _InheritedClock(now: _now, child: widget.child);
}

class _InheritedClock extends InheritedWidget {
  final DateTime now;

  const _InheritedClock({required this.now, required super.child});

  // chamado quando o provider é reconstruído: os leitores devem
  // ser reconstruídos? Sim, se a hora mudou
  @override
  bool updateShouldNotify(_InheritedClock oldWidget) => oldWidget.now != now;
}

import 'package:flutter/material.dart';

class Highlighter extends StatefulWidget {
  final Color color;
  final Widget child;

  State<Highlighter> createState() => _HighlighterState();

class _HighlighterState extends State<Highlighter> {
  bool _touched = false;
  bool _hovered = false;

  @override
  Widget build(BuildContext context) {
    // MouseRegion: os movimentos do mouse; Listener: os contatos
    // do dedo (ou os cliques), no nível mais baixo
    return MouseRegion(
      onEnter: (_) => setState(() => _hovered = true),
      onExit: (_) => setState(() => _hovered = false),
      child: Listener(
        onPointerDown: (_) => setState(() => _touched = true),
        onPointerUp: (_) => setState(() => _touched = false),
        onPointerCancel: (_) => setState(() => _touched = false),
        // AnimatedContainer: uma mudança de cor ANIMADA (200 ms)
        child: AnimatedContainer(
          duration: const Duration(milliseconds: 200),
          color: _touched || _hovered ? widget.color : Colors.transparent,
          child: widget.child,
        ),
      ),
    );
  }
}

// lib/ex15_behaviors/long_press.dart - um botão de toque longo
// -------------------------------------------------------------------------
//     LongPressButton(duration: Duration(seconds: 1), onAction: remove, child: ...)
// A ação só é executada se o botão for mantido pressionado durante
// toda a duração: uma proteção contra toques acidentais. Um anel
// se preenche durante o toque.
// O preenchimento é uma ANIMAÇÃO: um AnimationController produz um
// valor que vai de 0 a 1 durante a duração dada, a cada quadro da
// tela. Ele precisa de um "ticker" (a pulsação dos quadros): o mixin
// SingleTickerProviderStateMixin o adiciona ao objeto State. Um MIXIN é
// a maneira do Dart de reutilizar código em várias classes (veja
// autofocus.dart).
// =========================================================================

import 'package:flutter/material.dart';

class LongPressButton extends StatefulWidget {
  final Duration duration;
  final VoidCallback onAction;
  final Widget child;

  const LongPressButton({
    super.key,
    this.duration = const Duration(seconds: 1),
    required this.onAction,
    required this.child,
  });

  @override
  State<LongPressButton> createState() => _LongPressButtonState();
}

// "with": o objeto State recebe, além disso, o código do mixin
class _LongPressButtonState extends State<LongPressButton> with SingleTickerProviderStateMixin {
  late final AnimationController _animation;

  @override
  void initState() {
    super.initState();
    // vsync: this: o ticker fornecido pelo mixin
    _animation = AnimationController(vsync: this, duration: widget.duration)
      // o fim da animação: o toque durou o suficiente
      ..addStatusListener((status) {
        if (status == AnimationStatus.completed) {
          _animation.reset();
          widget.onAction();
        }
      });
  }

  // quando o widget é removido: nenhuma animação órfã
  @override
  void dispose() {
    _animation.dispose();
    super.dispose();
  }

  void _start() => _animation.forward(from: 0);

  // o dedo levanta cedo demais: o anel se esvazia
  void _stop() {
    if (_animation.isAnimating) _animation.reverse();
  }

  @override
  Widget build(BuildContext context) {
    return GestureDetector(
      onTapDown: (_) => _start(),
      onTapUp: (_) => _stop(),
      onTapCancel: _stop,
      // AnimatedBuilder: reconstrói APENAS este trecho, a cada quadro
      child: AnimatedBuilder(
        animation: _animation,
        builder: (context, child) => Row(
          mainAxisSize: MainAxisSize.min,
          children: [
            SizedBox(
              width: 22,
              height: 22,
              child: CircularProgressIndicator(value: _animation.value, strokeWidth: 3, color: Colors.red),
            ),
            const SizedBox(width: 8),
            child!, // o filho, construído uma vez por todas
          ],
        ),
        child: widget.child,
      ),
    );
  }
}

[..addStatusListener(...)]: quando a animação chega ao fim ([completed]), o toque durou o suficiente: a animação volta a zero e a ação é executada;

// lib/ex15_behaviors/autofocus.dart - um comportamento em um MIXIN
// -------------------------------------------------------------------------
// A segunda maneira de reutilizar um comportamento: um mixin sobre State.
//     class _MyPageState extends State<MyPage> with FocusOnStart { ... }
// O objeto State recebe um FocusNode (startFocus), que assume o foco
// assim que a tela é exibida e que é liberado junto com ela: o mixin
// completa o initState e o dispose da classe que o usa.
// "on State<T>": este mixin só se aplica a um objeto State, cujos
// métodos ele pode portanto usar (initState, dispose, mounted...).
// (Para um simples campo, o parâmetro autofocus: true do TextField faz
// a mesma coisa: o mixin mostra o mecanismo, reutilizável para outra coisa.)
// =========================================================================

import 'package:flutter/widgets.dart';

mixin FocusOnStart<T extends StatefulWidget> on State<T> {
  final startFocus = FocusNode();

  @override
  void initState() {
    super.initState(); // o initState da classe (ou do mixin) "acima"
    // após a primeira exibição: o campo existe, damos-lhe o foco
    WidgetsBinding.instance.addPostFrameCallback((_) {
      if (mounted) startFocus.requestFocus();
    });
  }

  @override
  void dispose() {
    startFocus.dispose();
    super.dispose();
  }
}
    • linha 17: um mixin que só se aplica a um objeto [State] ([on State<T>]): ele pode, portanto, usar seus métodos;
    • linha 18: o objeto [State] que usa o mixin recebe este campo;
    • linhas 21–25: o mixin [initState] é complementado: [super.initState()] chama o da classe “pai” (a de [State], ou outro mixin). Depois da exibição inicial, o campo existe: o foco é dado a ele. [mounted]: o objeto [State] ainda está na árvore?;
    • linhas 30–32: ele também complementa [dispose], para liberar o [FocusNode].

// celular, tecla Esc) resolve o Future com null: isso é tratado
// como um "não".

import 'package:flutter/material.dart';

Future<bool> confirm(BuildContext context, String message) async {
  final answer = await showDialog<bool>(
    context: context,
    // AlertDialog: um diálogo Material, com um título, um conteúdo e botões
    builder: (context) => AlertDialog(
      title: const Text('Confirmation'),
      content: Text(message),
      actions: [
        // autofocus: o botão "No" (a escolha menos perigosa) recebe o foco
        TextButton(autofocus: true, onPressed: () => Navigator.pop(context, false), child: const Text('No, go back')),
        FilledButton(
          style: FilledButton.styleFrom(backgroundColor: Colors.red),
          onPressed: () => Navigator.pop(context, true),
          child: const Text('Yes, confirm'),
        ),
      ],
    ),
  );
  return answer ?? false; // null: diálogo fechado sem resposta
}

    • linhas 23–25: [AlertDialog] é a caixa de diálogo do [Material Design]: um título, um conteúdo e botões;

import 'package:flutter/material.dart';

import 'confirmation.dart';

typedef Contact = ({int id, String name});

void main() {
  runApp(
    MaterialApp(
      debugShowCheckedModeBanner: false,
      theme: ThemeData(colorSchemeSeed: Colors.indigo),
      home: const ContactsPage(),
    ),
  );
}

class ContactsPage extends StatefulWidget {
  const ContactsPage({super.key});

  @override
  State<ContactsPage> createState() => _ContactsPageState();
}

class _ContactsPageState extends State<ContactsPage> {
  final List<Contact> _contacts = [
    (id: 1, name: 'Jean MARTIN'),
    (id: 2, name: 'Alice DURAND'),
    (id: 3, name: 'Luc GERMAN'),
  ];
  String _message = '';

  // uma função async: ela "espera" a resposta do usuário
  Future<void> _remove(Contact c) async {
    final yes = await confirm(context, 'Delete the contact ${c.name}?');
    // após um await, a tela pode ter desaparecido: verificamos se ainda está lá
    if (!mounted) return;
    if (!yes) {
      setState(() => _message = 'Deletion abandoned.');
      return;
    }
    final position = _contacts.indexOf(c);
    setState(() {
      _contacts.remove(c);
      _message = '${c.name} has been deleted.';
    });
    // ScaffoldMessenger: exibe uma mensagem passageira na parte de baixo da tela
    ScaffoldMessenger.of(context).showSnackBar(
      SnackBar(
        content: Text('${c.name} deleted'),
        action: SnackBarAction(
          label: 'Undo',
          onPressed: () => setState(() {
            _contacts.insert(position, c);
            _message = '${c.name} is back.';
          }),
        ),
      ),
    );
  }

  Future<void> _removeAll() async {
    final yes = await confirm(context, 'Delete the ${_contacts.length} contacts?');
    if (yes && mounted) {
      setState(() {
        _contacts.clear();
        _message = 'All the contacts have been deleted.';
      });
    }
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Example 16 - a confirmation dialog')),
      body: ListView(
        padding: const EdgeInsets.all(16),
        children: [
          for (final c in _contacts)
            ListTile(
              leading: const Icon(Icons.person),
              title: Text(c.name),
              trailing: IconButton(
                icon: const Icon(Icons.delete_outline, color: Colors.red),
                onPressed: () => _remove(c),
              ),
            ),
          if (_contacts.isEmpty)
            const ListTile(
              title: Text('No contact.', style: TextStyle(color: Colors.grey)),
            ),
          const SizedBox(height: 12),
          Align(
            alignment: Alignment.centerLeft,
            child: FilledButton(
              style: FilledButton.styleFrom(backgroundColor: Colors.red),
              // null: botão desabilitado quando a lista está vazia
              onPressed: _contacts.isEmpty ? null : _removeAll,
              child: const Text('Delete all'),
            ),
          ),
          const SizedBox(height: 12),
          if (_message.isNotEmpty) Text(_message, style: const TextStyle(color: Colors.indigo)),
        ],
      ),
    );
  }
}
